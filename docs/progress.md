# kakao-agent 작업 현황

## 2026-10-24

### 구현

- 수강생이 실습을 끝낸 뒤 허용 별칭을 backend 호출 없이 제거할 수 있도록 `kakao-agent remove 별칭`을 추가했다.
- MCP는 요청마다 허용 목록을 다시 읽어, 이미 열린 AI 도구 세션에서도 `remove` 직후 철회를 반영한다.
- MCP의 미허용 방, 로컬 수집 실패를 예상 가능한 `ToolError`로 바꿔 서버 traceback 대신 복구 가능한 오류만 모델에 전달한다.
- README에 별칭이 본문 개인정보를 익명화하지 않는다는 경계와 별칭 제거 절차를 추가했다.

### 검증

- `uv run pytest -q`를 같은 환경에서 두 번 실행해 각각 32개 통과를 확인했다. 실 MCP stdio 테스트는 미허용 방의 안내 문구를 확인하고 backend 호출 전에 멈추며, 실행 중인 서버에서도 `remove` 직후 빈 목록을 반환하는지 확인한다.
- `uv run ruff check src tests`를 통과했다. 격리한 `uv tool install .` 환경에서 `init → allow → remove → rooms`를 실행해 허용 목록이 빈 상태가 되는 것을 확인했다.

### 남은 검증과 공개 기준

- 실제 Windows 카카오톡 창의 접근성 텍스트와 실제 Mac DB 구조는 fixture 검증과 구분해 별도 실기기에서 확인한다. 개인 대화·방 제목·계정 식별값은 읽거나 기록하지 않는다.

## 2026-10-22

### 구현

- 클립보드 backend를 제거했다. macOS는 자체 로컬 DB backend, Windows는 자체 열린 창 접근성 backend로 분리했다.
- macOS backend는 기기·로컬 계정 표식으로 읽기 키를 만들고, 후보 DB를 읽기 전용으로 연 뒤 선택한 방의 텍스트만 찾는다. `prepare`는 원문·방 제목을 읽지 않으며, DB 개방이 실제로 확인됐을 때만 계정 식별값을 로컬 설정에 저장하고 출력하지 않는다.
- macOS의 `discover`는 사용자가 직접 실행한 CLI에서만 방 ID와 제목을 보여 준다. MCP에는 `kakao_rooms`, `kakao_read`만 남겨 전체 방 탐색을 막는다.
- macOS의 방 탐색은 `NTChatRoom`을 기준으로 읽고, 오픈채팅 이름은 `NTOpenLink`, 이름이 비어 있는 방은 방 제목 메타·1:1 상대·참여자 이름 순으로 보완한다. 임의의 보조 테이블을 방 목록으로 선택하지 않는다.
- macOS의 메시지 읽기는 `NTChatMessage`만 대상으로 `(sentAt, logId)` 순서를 사용한다.
- Windows backend는 Win32 최상위 창을 열거한 뒤, 카카오톡 프로세스의 별도 채팅창 클래스와 지정한 제목이 정확히 일치하는 창 하나의 접근성 텍스트만 읽는다. 카카오톡 메인창은 제외하며, 클릭, 입력, 복사, 전송을 하지 않는다.
- 허용 목록 검사, 미허용 방의 backend 선차단, 과도한 길이 차단, 연락처 일부 치환을 유지했다.

### 검증

- 자체 테스트: `uv run pytest -q`에서 30개 통과.
- 정적 검사: `uv run ruff check src tests` 통과.
- `sqlcipher3`를 실제 설치하고 메모리 DB의 읽기·쓰기 기본 동작을 확인했다. 카카오 DB에는 연결하지 않았다.
- GitHub Actions: macOS·Windows와 Python 3.11·3.13 조합 4개 행에서 설치, 테스트, 정적 검사를 실행한다.
- 실제 MCP subprocess로 도구 목록과 미허용 방의 backend 선차단을 확인한다.
- Windows 창 식별은 `EnumWindows`와 카카오톡 프로세스 ID, 채팅창 클래스, 정확한 제목을 함께 검사하도록 단위 테스트로 고정했다. 다만 실제 Windows 카카오톡 화면 검증은 아직 하지 않았다.

### 남은 검증과 공개 기준

- Mac: 카카오톡 실행 상태에서 원문·방 제목 없이 활성 계정을 찾아 정확한 DB 파일을 계산하고, SQLCipher 읽기 전용 개방까지 확인했다. 실제 CLI `discover`가 전체 로컬 방 목록을 읽고, 특정 방 제목의 핵심어가 하나의 방으로 식별되는 것을 확인했다. 그 방의 최신 텍스트 10개를 읽는 경로도 별도 로컬 검증으로 확인했다. 실제 대화·방 제목·ID는 저장하지 않았다.
- Windows: 같은 제목의 창 하나를 열어 `allow → read`로 접근성 텍스트가 실제 보이는 범위와 맞는지 확인한다. Windows 실기기는 아직 없다.
- 공개 전: 예제 설정·테스트 출력·Git 이력에 실제 방 이름, 대화, 계정 식별값, 키가 없는지 다시 검사한다.
- 자동화 테스트는 개인 Mac DB와 실제 Windows 카카오톡 창의 결과를 보증하지 않는다.
